## (b) Findings

1. runner.py 6497-6512, high. CONFIRMED: probe case B gave True on 4 of 4 retries. The wake's sessions each kept one model turn, then failed with `LLMUnavailable`. `session_fail` keeps the turns, so each retry makes `last` the previous retry. Then `first` is None and the rule returns True. A prompt that grows past the window on turn 2 is given back forever, and `model_stop` stops the run as a down model. Fix: read the end as the wake's own when the current session kept a model turn, and start `first` after the wake's last commit, not its last kept turn.
2. runner.py 6512 and loop.py 572-577, high. CONFIRMED: probe case A gave True on 4 of 4 retries with no session between. A wake at the frontier head that can never answer stops every run after three ends, and it never reaches quarantine. The stop line says the model does not answer, and the model may be up. Fix: after one instrument end, run a different wake or a small model call as the probe, and spend the attempt when the probe answers.
3. cli.py 728, high. CONFIRMED: on the dry1 copy with `model_down` set and 5 asks, `cmd_agenda` printed the asks and no stop line. `render_state` runs only when no ask waits. The claim says `rota agenda` shows the stop. Fix: print `model_down` first in `cmd_agenda`, before the asks.
4. db.py 1001-1013, low. CONFIRMED: m97 (refs s1 and s2, landed ruling) was unresolved when s1 moved, then quarantined. After s2 moved, it kept `moved_refs = ["s2"]` and stayed quarantined. A move before the quarantine or before the landing does not count. A ref that no write names never closes the message. Fix: compare each ref's state with a snapshot taken when the ruling lands, or keep moves from the landing on, whatever the message status.
5. scheduler.py 1603 and traceview.py 160, low. CONFIRMED: on a dry1 copy opened only by `connect_readonly`, `frontier_readonly` raised an `OperationalError` with the text "no such column: told". The cockpit server overlay and `rota ls` reach it. `SCHEMA_MARK` did not change, so `schema_stale` does not see the gap. Fix: read `told` and `moved_refs` with a fallback when the column is absent.
6. loop.py 562-565, low. PLAUSIBLE: the code read shows it. Only a committed session removes `model_down`, and `rota run` does not read the row at its start. After the model is back, a run whose sessions answer and fail on their own keeps the old stop line on the agenda. Fix: remove the row at the first session that keeps a model turn.
7. runner.py 6497-6508, low. PLAUSIBLE: the code read shows it. `first` resets only by the wake's own answer. Take a wake with an old given-back end, then other sessions that answer, then a real outage. The wake's next end reads as its own, and the outage spends an attempt. Fix: bound `first` to the current run of `model_stop`.

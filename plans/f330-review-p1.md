## (b) Findings

1. **The quiet park's second bound pass forgets the counts of held-back wakes.** `rota/core/scheduler.py:1601`. Low. CONFIRMED. `quarantine_stalled` deletes every unquarantined `tick_attempts` row whose key is not in `live` and names no live batch. The first pass reads `live` from `all_wakes`. The second pass reads `live` from the park alone. A wake that `waiting_filter` holds back is in `all_wakes` and not in the park, so its count goes. The probe put `architect|tick:grouping|tk9` at 2 attempts with an open Architect question: after one `frontier` call the row was gone. Fix: run one bound pass. Read `wakes = quarantine_stalled(conn, all_wakes(...) + quiet_park(conn))`, then take `ready` as `waiting_filter` of the wakes that are not `do:park`, and return `ready` or the `do:park` wakes.
2. **A seat that waits on an answer counts as quiet.** `rota/core/scheduler.py:1599-1601`. Low. PLAUSIBLE. The quiet is `ready`, the list after `waiting_filter`. The probe shows the park with a held Architect wake beside it. A held wake that could move the batch is rare: the answer comes as a message wake, and message wakes are never filtered. A Developer who waits on the Tester with the batch's fix key quarantined is the one shape that parks a batch a seat could still move. Fix: decide the quiet from the list before `waiting_filter`, or state in the `quiet_park` docstring that a held wake counts as quiet, and why.
3. **`frontier_readonly` shows no park and shows a quarantined wake.** `rota/core/scheduler.py:1604-1608`. Low. CONFIRMED. On dry1's copy `frontier` gives the park, and `frontier_readonly` gives `tester|tick:tests_missing|bg_1`, a key quarantined at 3. The cockpit and the status line read the readonly view, so they show a Tester wake that will never run and no park until `step` performs it. The quarantined wake predates the commit. Fix: filter the readonly list by the quarantined keys with a read, and add the park with the same filter.
4. **Two bare pairs in one reply name no line.** `rota/roles/api.py:12828-12841`. Low. PLAUSIBLE. "1 now 2 drop" on a two-line page gives `line_words` `{1: '1 now', 2: '2 drop'}` and `named` empty. `_backed` names a line only from `reading.named`. If the door passes the whole reply as `said`, a two-item shift page refuses both answers, as dry1's one-item page did. If it passes each line's words, each pair is bare and lands. Fix: probe `rulings.rule` with "1 now 2 drop" on a two-line shift page, and if it refuses, let `_menu_pair` read a reply that is a run of pairs.

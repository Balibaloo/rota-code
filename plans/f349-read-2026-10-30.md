## 2. What the code holds

It finds the ops that reach the enclosing top-level function through the call graph. A mode "meets" a text when the mode holds one of those ops. The text fails when such a mode lacks the named call and no guard asks for that call (observed: `findings`, `_refusal_calls.py` 360 to 385).

`api._offer` (`api.py` 298) returns the text unchanged. Under pytest it records an `Offer(op, args, then, frames, said)` on `ctx.offers`. In a session it does nothing (`RECORD = False`, `api.py` 234). `sandbox.follow` (`sandbox.py` 5536) dry-runs each offer through the real doors. It also sets `not_in_mode` from `held_calls`, which is the sandbox's functions narrowed by `_wake_mode_set` (`sandbox.py` 5521). So `_offer` gives a mode check only when a test raises that refusal in a sandbox narrowed to the mode. The lint does not read `_offer` (observed).

## 4. Proposal

**Place: one helper in `api.py`, `_holds(ctx, call) -> bool`, which reads `call in (_wake_mode_set(ctx) or all ops)`.** Each true place names its call only under `if _holds(ctx, "x.y"):`. Where the mode lacks the call, the text gives the fact and the mode's own route if one exists, else the fact alone.

What already exists (observed):

- `_wake_mode_set` and `_wake_mode_tools` (`api.py` 6386, 6402) read the runtime list that `runner._wake_allow` builds. The follower reads the same list.
- `_holds_tester_route` (`api.py` 5726) is this helper for one call, `msg.answer_tester`.
- Inline checks of the same form: `"problem.assert" in _wake_mode_tools(ctx)` (api.py 2026), `msg.challenge_vision_keeper` (6923, 7049), `brief.segment` (sandbox.py 3852).
- A second source: `ctx.working_set` (sandbox.py 833), read by `_owner_call` and `ledger_log` (api.py 15177, 15439, 15533). Two sources of the held set exist. The helper should read one of them, `_wake_mode_set`, because review p1 finding 1 made that the runtime list.

The candidates:

- **(a) Per mode, by a lookup of the held set.** Covers all 9 places. The lint changes nothing: `_test_guards` reads a dotted string in the `if` test as a guard, so `if _holds(ctx, "surveys.attest"):` passes. The two false positives also go green under the same guard, because the guard holds at runtime anyway. All 7 parametrized cases stay and turn from xfail to pass. `KNOWN_UNHELD` empties. No test is lost.
- **(b) No call where the mode lacks it, and the mode's own route instead.** This is the else branch of (a), not a separate place. Alone, it needs the same lookup to know which mode lacks the call.
- **(c) Every refusal through `api._offer`.** 5 of the 7 already go through it, and they still fail. `_offer` makes the follower check a test that raises the text in a narrowed mode. The lint does not read `_offer`. So (c) closes nothing alone. It is worth doing for places 4 and 8, the raw texts, so that a follower test can hold them.

The test changes under (a):

- `KNOWN_UNHELD` becomes `{}`, and `test_the_table_names_only_keys_the_lint_reads` still holds.
- One follower test for each of places 7, 8 and 9. The lint cannot see them, because they are shared texts.
- `tests/rota/test_f33_debts_name_open_frames.py` loses the seven debts.
- Optional: drop the "shared" exemption for a text whose reach the static reading can narrow to a role. That is a lint change. It is not needed for the frame's end.

**Price.** One pass and one review: about 60k tokens for the pass, which covers 9 sites, one helper and three follower tests, and about 30k for the review. About 100k in 2 to 3 cycles, which matches the head audit's price of 3 cycles and about 100k (`plans/rootfix-audit-2026-10-30-head.md` line 62). The bare-name tier is a separate frame. A triage read costs 1 cycle, and a lint over bare names with a fix costs 2 to 3 more (reasoned).

## 4. The read

The door is `_pass_lines_check`, called by `verdicts_emit` at api.py 15873, with `_first_pass_hold` after it at 15874. Its text is the one refusal of every case: "a pass names, for each criterion, the added line of the diff that meets it ... If no added line meets c_1, that is a fail on it" (observed: api.py 16543, 16699, 16740). The prompt says the same: "A criterion with no added line that meets it looks like it fails" (observed: `review.md` step 1). The loop ends only when the seat copies a line the door admits, or sends a fail, or the runner stops it after two or three same refusals and the key quarantines at 3 (observed: runner.py 6005 to 6013, `tick_attempts`).

1. The cause: the door and the prompt admit two states of a criterion, met by an added line or failed. A criterion that holds because nothing changed, night 174's c_3, has no added line, and the comment that states it is refused by `_why_refused`, so the seat fails it or loops (observed: night174-read.md line 71, api.py 16176; reasoned: the two-route text).
2. Night 175 is a second cause under the same door: a weak seat sends the hunk instead of the line, and F37's landed rule refuses a pasted run by design; the loop costs 3 Critic sessions and one Developer rewrite of right code before a fifth seat copies the line (observed: `tool_calls`; reasoned: the F37 design note at stack line 1606).
3. Unbuilt: a route for a criterion that no added line meets and the code still satisfies, with evidence a kept line of the diff's context or the criterion's passing test, and a `lines=` form that the prompt names for it; and a verdict-less exhaust that tells the Developer the tests pass, so it does not rewrite the code (reasoned: no door, prompt line or fact names either; night 174 W12's not-read list asks "why the pass door took `def clear() -> bool:` for an invariant criterion").

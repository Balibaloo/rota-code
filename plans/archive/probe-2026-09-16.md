## 4. What a frame is

A frame is one unit of work that the stack holds and one session owns. Four things make work a frame: an observable ends-when, a visible end, countable attempts or a loop through agents, and a named wait. A frame goes on the stack before the work starts. The record is five lines: what, ends when, waits on, a pointer to the reasoning, and a dated status. Closed frames leave the file.

## 5. On a goal

I grill Roman every time. I ask one question at a time, each with a recommended answer. I stop when the work quantises into frames. I push a frame before I start it. I check my reading of the ask with Roman before I act.

## 6. The fix loop

I diagnose and write the fix brief. An agent implements, re-records the touched cases, and returns the diff and the result. I review from a context that never read the files. The split keeps my context in the smart zone: bulk reading goes to agents, and the review does not depend on the files. A one-line door is the exception. One frame per wall, one status line per cycle.

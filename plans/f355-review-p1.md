## (b) Findings

1. runner.py 6436, high. PLAUSIBLE: the code read shows it, and no probe called a model. The give-back treats every `LLMUnavailable` as transient. `LiteLLMBackend.complete` wraps every exception (llm.py 634), so an auth error, a bad model name or a context overflow gives back too. `urllib.error.HTTPError` is a `URLError`, so an Ollama 404 or 500 gives back (llm.py 507). A prompt too large to answer in 300 s times out the same way every time. Such a wake never spends an attempt and never reaches quarantine. It stays at the head of the frontier and blocks the wakes behind it until the session limit. The Principal gets no report. Fix: give back only for a timeout or a refused connection, and count the ends with no answer in a row, then stop the run and name the model.
2. db.py 974-980, low. CONFIRMED: on a copy of dry1.db, m99 (refs s1 and s2, landed r_m99) became `answered` on a moved write of s2 while s1 had not moved. The move of any named row closes the message, and the move need not come from the ruling. Fix: close only when every ref of the message has moved since the ruling landed, or when the ruling's own rows move.
3. db.py 441 and predicates.py 1743, low. CONFIRMED: on a copy of dry1.db opened by `db.connect`, `predicates.quarantined` raised `OperationalError('no such column: told')`. Every frontier caller in the tree opens with `init_db` first (cli.py 525, onboard_run.py 35, tui.py 801), so no live path fails today. `SCHEMA_MARK` did not change, so `schema_stale` does not see the gap. Fix: add the `told` check to `connect`, or read `told` with a fallback when the column is absent.
4. scheduler.py 2549, low. PLAUSIBLE: `undo_dispatch` decrements the key whether or not this call counted it. The fixtures call `run_session` with no `note_dispatch` (fixtures.py 1671, 1772). A replay miss does not give back, so only a test that raises a live `LLMUnavailable` reaches it. Fix: carry the count from `note_dispatch` on the wake, and give back only when the count is set.
5. loop.py 337-340, low. PLAUSIBLE: the code read shows it. A committed `tick:quarantined` marks every quarantined message told, whatever the Liaison's report names. A message quarantined after the wake was built is marked told and never said. The tick keys have the same gap through `reported`. Fix: mark told only the messages whose refs were in the wake that ran.

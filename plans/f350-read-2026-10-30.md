## 1. Purpose

NULL for an inherited test is by design (observed). The design predates the case of a merged Tester test, and frame 207 later chose to recover the Tester origin by path, not by a copied criterion (observed). No ruling of Roman names the case (reasoned: none found).

1. The build is `8fb78e662`, 2026-09-09 13:05, "feat(harness): the repository's own tests join the batch" (observed: `git log -S "VALUES (?, ?, NULL, ?, ?)" -- rota/core/harness.py`). Its body: "At start the batch inherits every test file the worktree already has, as a tests row with no criterion. ... `tests.criterion_id` allows null for that row". The cause was tipsY: "The repo's own tip test was in the tree and never ran".
2. The schema says the same, `rota/core/schema.sql` 566 to 569 (the probe's line 554 has drifted): "NULL for a test the repository already had. The batch inherits the repository's own tests at start". The docstring of `harness.inherit`, `rota/core/harness.py` 430 to 439, says: "The repository's own tests join the batch, with no criterion." The insert is at 452 to 454.
3. `inherit` does not ask who wrote a file. A merged Tester test is in the tree at the next batch's start, so it is "a test the repository already had" (observed: `harness.py` 441 to 454, `project_tests` 410 to 428).
4. Frame 207 met exactly this case, night 140: "`inh_f3b0c3db` is bg_1's own Tester test, byte-equal to `tst_cr1`, inherited by bg_2 at the merge with no criterion" (observed: `plans/archive/stack-2026-10-13.md` line 5). Its fix, `8888ea93`, 2026-10-11, added `tester_paths` and `_own`, `harness.py` 66 to 82: "A test keeps the filter of the batch that wrote it." The join is `t.criterion_id IS NOT NULL AND t.batch_id != ? AND b.status = 'merged'`. So frame 207 reads the criterion link from the merged batch's row and left the copy's NULL in place (observed). The frame closed 2026-10-13 05:47 with 0 of 8 batches looping on such a test (observed: the same file, frame 207's last status).
5. A copied criterion would be wrong for the later batch (reasoned). The criterion belongs to a merged batch. `invariants.i1` checks one test per criterion, and a copy would give that criterion two tests. `scheduler.park_reds` would call a red copy "own" for a criterion the batch does not hold. `sandbox._challenge_evidence` would route a challenge to a criterion of a closed batch. So NULL keeps a later batch's readers from treating the copy as the test of a criterion it did not write.

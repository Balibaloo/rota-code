## 2. The rule today

1. "line N", "lines N to M" or "note N" names line N when it is the subject. The subject is within the first two words (`_SUBJECT_LEAD`), after "on" or "in", or after a comma (`_subject_parts`, rule K0). Ordinals ("the first line"), "every line" and "the rest" also name lines.
2. A bare number names a line only at the clause start before "is", "are", "'s" or ":" (`_LINE_REF` group 2, `_BARE_VERB`), or in a list of two or more numbers ("2 and 3"). The probe q2_rule.py shows "1 try again", "1 ok", "1. drop", "1: drop", "drop 2" and "1 ok 2 try again" all name no line.
3. A quote of the line's own words never names a line. `line_words` takes no page text, and `menu_ruling` passes none. His quoted spans are blanked before the reader runs, so a number inside a quote names nothing.
4. The fallback runs for each line that no span names, in three cases: no clause names any line, the reply matches `_APPROVES`, or the reply is a bare agreement. Otherwise an unnamed line gets `None`. In the menu, a line with `None` takes approve unless the seat quotes his words for a change.
5. `groups.pop` removes the whole-reply group only when two groups or more exist, that is, when a clause names some lines and the reply also approves. When the fallback is the only group, the group stays, so one clause holds every line. The `missing` refusal (api.py 14727-14735) then asks for an option on each of those lines.

`_line_cues` (api.py 13271-13394) is not the binder. Its only caller is `LineReading._cued`, which serves the cue doors. `line_words` reads `_clause_spans`, `_subject_parts`, `_line_reading(...).refs` and `_ORDINAL_LINE`.

## 4. The shape of the fix

- The change goes into `_subject_parts`, or into `_bare_subject` in the path of `_BARE_LIST`. Today one number names a line only before "is" or "are". The fix: a bare number at the start of a clause names line N when 1 <= N <= size. So "1 try again" binds line 1 only, line 2 gets `None`, and line 2 takes approve.
- The fix must also cut a clause at each "N word" pair, as rule K0 cuts at a comma. Probe q4_menu_form.py shows that "1 ok 2 drop" lands today as `{'I1': 'approve', 'C1': 'contest'}`, because the fallback binds both lines. A fix at the lead of the reply only binds line 1. Probe q4_menu_form_fixed.py then shows "line 1 ok 2 drop" and "line 1 ok line 2 drop" refused: "line 2: no clause of his names line 2, so line 2 takes approve". Only "line 1 ok, line 2 drop", with the comma, lands. So the fix must read the menu form as clauses, else it breaks a form that lands now.
- The fix must keep the guard of `_bare_subject`: "3 at most" and "I want 2 examples" name no line. With N <= size alone, "2 examples are too many" on a page of three lines reads as line 2.
- Expected calls of recorded cases that move: none. Probe q4_fix_reach.py found no recorded reply with a clause that leads with a bare number not before "is" or "are". The two L1 replies that lead with a number, "3 is wrong" and "1 is fine", are named today already.

MODE: term_collision — one word, defined so far from one place at a time.

`[glossary.lookup]` is what earlier sessions wrote. Each of them saw this word in
one area and described how it looked from there. None is wrong about where it
looked. None of them is the word.

`[code.concordance]` is the word everywhere this project uses it: where it is
declared, what is done with it, and the files that pass it between them. **Write
the definition from that.** Not a summary of the readings — adding them together
gives a vaguer word, not a truer one, and the sense you are looking for is the
one none of them could see from where it stood.

Then `glossary.synthesise(ids=[...], sense_short=..., sense_body=...)`. It
replaces the readings and they stay readable underneath.

Say what the thing **is** and what it is **for**, in a sentence that could only
be written about this project. Test it by putting a different word in its place:
if it still reads true, it is a category and not a meaning.

If two rows are genuinely two different things this project means by one word,
that is a real collision and not yours to settle: `msg.report_liaison` with both
ids. If two rows are one sense written twice in different words, with nothing
to compose, `glossary.same(keep, drop, why)` records that — `why` saying, in
the senses' own words, what they share.

`code.source` any file the concordance makes you want to read whole.

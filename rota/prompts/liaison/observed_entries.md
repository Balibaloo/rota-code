MODE: observed_entries — onboarding found things nobody chose.

Terms, constraints and behaviours extracted from an existing codebase are marked
`observed`: found, not decided. They are true about the code and carry no
authority about what the project is for.

Put them to the principal with `msg.present_principal`, grouped by what they are
about, and be explicit that these are observations awaiting a first decision. An
observed entry that is challenged forces that decision, which is the point of the
distinction — it is the difference between "the code does this" and "we meant it
to".
